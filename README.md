# JinSheet — Excel, CSV & Office Viewer

JinSheet는 CSV·TSV와 제한된 XLSX 통합문서를 VS Code에서 로컬로 확인·수정하고, Word·PowerPoint·PDF 문서를 로컬에서 페이지 렌더링으로 읽기 전용 미리 보는 확장입니다. 데이터 보존을 우선하며, 지원 여부를 판정하지 못하는 XLSX는 수정 저장을 막고 이유를 표시합니다. XLSX 수식은 계산하지 않습니다.

화면 기본 언어는 영어이며, VS Code 표시 언어가 한국어이면 한국어로 전환됩니다. 그 외 표시 언어에서는 영어를 사용합니다.

## 지원 범위

| 형식 | 보기 | 편집·저장 | 제한 |
| --- | --- | --- | --- |
| CSV/TSV | 지원 | 지원 | UTF-8 및 UTF-8/UTF-16 BOM만 쓰기. 최대 10 MiB·10,000행·100,000셀·행당 1,000열. 구분자를 확실히 추정하지 못하면 읽기 전용 오류를 표시합니다. |
| XLSX | 지원 | 제한 지원 | 수식이 없고 검사기가 아는 단순 OOXML 패키지만 저장합니다. 셀 수정·비우기와 행 삽입·삭제를 지원합니다. 최대 50개 행·10개 열의 표준 고정 창을 표시하고 셀 저장 뒤에도 원본 설정을 보존합니다. 분할 창, 비정상 설정, 고정 영역과 겹치거나 시트 범위를 벗어난 고정 창은 읽기 전용입니다. 열 너비 설정은 읽어 화면에 반영하고 셀 저장 뒤에도 보존합니다. 열 너비·열 서식 정의가 있는 시트에서는 열 삽입·삭제를 막습니다. 최대 압축 20 MiB, 512개 항목, 압축 해제 64 MiB·항목당 16 MiB·압축률 200:1·100,000셀입니다. |
| XLSM | 지원되는 OOXML의 값 보기 | 미지원 | 매크로를 실행하지 않고 항상 읽기 전용입니다. |
| DOCX | 페이지 레이아웃 렌더링 | 미지원 | 확대·축소와 너비 맞춤을 지원하며 로컬 렌더러로 텍스트·표·이미지와 페이지 나눔을 표시합니다. Office와 완전히 같은 결과를 보장하지 않습니다. 주석·변경 내용은 표시하지 않습니다. |
| DOCM | 페이지 레이아웃 렌더링 | 미지원 | DOCX와 같은 로컬 렌더러를 사용하며 VBA는 실행하지 않습니다. |
| PPTX | 슬라이드 렌더링 | 미지원 | 확대·축소와 너비 맞춤을 지원하며 로컬 렌더러로 텍스트·도형·표·이미지와 기본 차트를 표시합니다. 복잡한 애니메이션·전환·미디어 재생은 지원하지 않습니다. |
| PPTM | 슬라이드 렌더링 | 미지원 | PPTX와 같은 로컬 렌더러를 사용하며 VBA는 실행하지 않습니다. |
| PDF | 페이지 렌더링 | 미지원 | 페이지 이동·확대·축소·너비 맞춤을 지원하며 최소 2배 해상도로 렌더링합니다. 최대 25 MiB·1,000페이지이며 암호가 필요한 파일은 렌더링하지 않습니다. |
| DOC, PPT | 미지원 | 미지원 | 구형 바이너리 형식입니다. DOCX/PPTX로 변환해야 합니다. |
| XLS, ODS | 미지원 | 미지원 | MVP 범위 밖입니다. |

수식·오류 값·리치 텍스트·셀 내부 미지원 구성요소·이름 정의·외부 관계·병합·차트·필터·검증 규칙·매크로·서명·미지원 OOXML 구성요소·불명확한 ZIP/XML 구조가 있으면 XLSX 저장을 차단합니다. 읽을 수 있는 경우 값과 수식/캐시값을 표시하며, 캐시값은 오래됐을 수 있습니다. 셀 스타일의 원본 인덱스와 수정하지 않은 패키지 항목을 유지합니다. 표준 날짜·시간·숫자·백분율 형식과 일반적인 사용자 지정 숫자·날짜 형식은 화면에 표시하되 원시 값은 편집·복사·저장에 사용합니다. XLSX의 명시적 RGB 글꼴·채우기 색, 굵게·기울임·밑줄, 크기, 가로 정렬과 기본 테두리도 화면에 반영합니다. 테마 기반 색상과 조건부 서식은 아직 표시하지 않습니다. 해석할 수 없는 사용자 지정 형식은 원시 값을 보여줍니다.

그리드는 viewport 범위만 렌더링하고 최대 60행×30열 범위로 데이터를 요청합니다. 스크롤 중 열 머리글은 위쪽에, 행 번호는 왼쪽에 고정됩니다. XLSX 파일에 저장된 열 너비는 열 때 반영됩니다. 열 머리글 경계를 드래그하거나 포커스 후 좌우 화살표 키로 열 너비를 48–640px 범위에서 조정할 수 있습니다. Auto-fit column은 해당 열의 전체 표시값을 기준으로 너비를 맞춥니다. XLSX의 너비 변경은 undo/redo와 dirty 상태에 연결되어 저장되며, 저장 후 다시 열어도 유지됩니다. CSV/TSV의 너비 조정은 편집기 탭을 닫을 때까지 유지되는 화면 설정입니다. 한 문서의 검색, 마우스 드래그·Shift+방향키 셀 범위 선택, 탭 구분 클립보드 형식의 CSV/TSV·XLSX 다중 셀 복사·붙여넣기, 수식 입력줄에서 셀 값 수정, 셀 선택 후 바로 입력, Enter/F2 편집, Home/End·Ctrl+Home/Ctrl+End·Ctrl+방향키 이동, 빈 XLSX 셀 값 입력과 Delete/Backspace로 선택 셀 값 비우기를 지원합니다. 붙여넣기는 최대 10,000셀·1,000,000자이며 한 번에 undo할 수 있습니다. 도구 모음에서 선택한 행 위에 행을 삽입·삭제하고 선택한 열 왼쪽에 열을 삽입·삭제할 수 있습니다. 미지원 구조가 있는 XLSX는 읽기 전용으로 열려 구조 변경도 비활성화됩니다. 전체 스크린 리더 검토와 대용량 성능 목표 시험은 아직 남아 있습니다. VS Code Web, 원격 파일 시스템과 다중 시트 복사는 지원하지 않습니다.

열 머리글을 눌러 오름차순·내림차순으로 정렬하고, Shift+클릭으로 보조 정렬 키를 추가하며 Ctrl/Cmd+클릭으로 해당 키를 해제할 수 있습니다. 정렬 우선순위는 머리글의 숫자로 표시합니다. 셀을 선택한 뒤 필터 입력란에서 해당 열의 텍스트 조건을 적용할 수 있으며, 서로 다른 열의 필터는 AND로 누적됩니다. 활성 필터가 있는 열 머리글에는 표시가 붙고, 해당 열을 선택하면 기존 조건을 다시 편집할 수 있습니다. 입력을 지우고 적용하면 선택 열의 필터만 제거되며 `정렬/필터 해제`는 모든 조건을 지웁니다. 첫 행 머리글 여부를 바꿀 수 있으며, `정렬/필터 해제`는 원래 행 순서를 복원합니다. 정렬·필터는 표시 순서만 바꾸고 파일의 행 순서는 변경하지 않습니다. 그 상태에서도 셀 편집·복사·붙여넣기·검색은 원본 행에 연결됩니다. 사용 행이 100,000개를 넘는 시트에는 정렬·필터를 적용하지 않습니다.

## 데이터 보존과 보안

- 저장 전 SHA-256 fingerprint를 확인합니다. 저장 중에도 다시 확인하고, 같은 폴더의 임시 파일을 재검증한 뒤 교체합니다. 외부 변경이 감지되면 저장을 중단합니다.
- XLSX는 대상 워크시트 XML에서 셀 값과 행·열 구조를 수정하고 ZIP 패키지를 다시 만듭니다. 저장 전후 ZIP CRC, 모든 비수정 항목의 내용 바이트, 재파싱 결과를 확인합니다.
- XLSX ZIP의 항목 수, 압축 후 크기, 압축률, 경로, 로컬·중앙 헤더, 데이터 범위, CRC를 검사합니다. XML은 엄격 모드로 파싱하며 DTD·엔터티·CDATA를 거부합니다. 지원 범위를 넘는 파일은 저장용으로 읽기 전용 처리하거나 안전 검사에서 거부합니다.
- DOCX/DOCM/PPTX/PPTM은 같은 ZIP 크기·경로·CRC 및 XML 안전 검사를 통과한 뒤 Webview 안의 로컬 렌더러로 표시합니다. PDF는 내장 PDF.js로 렌더링합니다. 매크로, 외부 링크, 임베디드 개체를 실행하지 않습니다. 모든 문서는 읽기 전용이며 렌더링은 Office 설치 없이 동작합니다.
- Webview는 nonce CSP와 타입·범위·입력 길이 검사를 사용합니다. 파일 내용은 네트워크로 보내지 않습니다.
- VS Code의 문서 백업 훅을 사용해 미저장 상태의 hot-exit 백업을 제공합니다. 별도 사용자 복구 UI와 원본 버전 보관 정책은 아직 구현되지 않았습니다.

이 확장은 스프레드시트 데이터를 중요하게 다루므로, 자체 파일을 백업한 뒤 사용하십시오. 알려지지 않은 오류나 파일 기능이 발견되면 저장하지 말고 Excel 등 원본 포맷을 완전히 지원하는 도구로 여십시오.

## 개발과 검증

Node.js 20 이상과 VS Code 1.90 이상을 사용합니다.

```sh
npm ci
npm test
npm run check
npm run test:host
npm run package
```

`npm test`는 CSV 파서, XLSX 보안·round-trip, Office 패키지 검증, PDF 입력, 저장·충돌·백업, Webview 메시지 범위를 검사합니다. `npm run build:renderers`는 고정된 로컬 Office/PDF 렌더러 자산을 생성합니다. `npm run test:host`는 지정하지 않으면 현재 OS용 VS Code Stable을 내려받아 Custom Editor 등록과 XLSX·CSV·Office 파일 열기를 확인합니다. 로컬 VS Code를 재사용하려면 `VSCODE_EXECUTABLE` 환경변수로 실행 파일 경로를 지정하십시오. GitHub Actions는 Linux·Windows·macOS에서 설치, 테스트, 감사와 VSIX 패키징을 실행합니다.
